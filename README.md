# 성과관리현황 검사 보조도구 (grad-rescue)

환경분야 특성화대학원 인력양성사업 · 성과관리현황 검수

시트 **하나**와 증빙 폴더 **하나**를 받아, 폴더 안 폴더까지 파일을 전부 열고
그 시트를 통째로 모형에게 맡겨 검사 칸을 채운다.

---

## 언제 쓰나

**검수도구(grad-doc-main)가 먼저다.** 이 도구는 그것이 막혔을 때 쓴다.

| 상황 | 쓸 것 |
|---|---|
| 파일 이름에 번호가 제대로 붙어 있다 | **검수도구** |
| 학교가 번호를 안 붙여 2단계 폴더 매칭이 막혔다 | 보조도구 |
| 3단계가 확인 불가를 너무 많이 뱉었다 | 보조도구 |

번호는 사람이 맺어 준 보증이다. 내용 추정보다 언제나 낫다.
번호가 있는데 이 도구를 쓰면 더 나빠진다.

---

## 검수도구와 무엇이 다른가

|  | 검수도구 | 보조도구 |
|---|---|---|
| 행을 맺는 법 | 파일명 앞 번호 | **증빙 내용** |
| 사업 지식이 있는 곳 | 코드 (`extract.py`·`compare.py` 2,048줄) | **검수기준 엑셀** |
| 규칙을 고치려면 | 코드를 고친다 | **엑셀을 고친다** |
| 모형이 하는 일 | 애매한 문자열 대조만 | 시트 하나를 통째로 |
| 열쇠 없이 | 0·1단계는 돈다 | **아무것도 못 한다** |
| 한 번에 | 워크북 전체 | **시트 하나** |
| Excel 설치 | 0단계에 필요 | 필요 없음 |

가장 큰 차이는 **판정 기준이 코드 밖으로 나왔다**는 것이다.
`보조도구 검수기준.xlsx` 가 정본이고, 프로그램은 그것을 읽어 돈다.
여기를 고치면 그게 곧 검사 규칙이 된다 — 재빌드가 필요 없다.
반대로 말하면, **여기가 틀리면 검사도 틀린다.**

## 어떻게 도는가

```
검수기준 엑셀  →  core.spec  →  core.prompt  →  글 한 장  →  모형
                                      ↑
   학교 엑셀 (core.book) · 별첨1 명단 · 증빙 글 전부 (engines.read)
```

`core.flow` 가 여섯을 잇는다.

1. **검수기준을 읽는다** — `core.spec`. 정본이 코드로 들어오는 유일한 문
2. **학교 엑셀을 연다** — `core.book`. 검증열은 **색(FCE4D6)으로** 찾고, 자료 열은 그것을 뺀 뒤 찾는다
3. **증빙 폴더를 통째로 읽는다** — `engines.read`. 폴더 안 폴더까지
4. **시트를 통째로 맡긴다** — `core.prompt` · `core.ask`
5. **수와 날짜는 코드가 센다** — `core.calc`
6. **검사 칸에 쓰고 내역을 뽑는다** — `engines.write` · `core.report`

### 모형에게 맡기지 않는 것

수와 날짜는 코드가 센다. 모형은 40시간과 4시간을 헷갈리고, ISBN 체크디지트를
못 세고, `25-02-10 ~ 25-02-14` 를 5일이라 했다가 4일이라 했다가 한다.
**같은 답을 내는 것 자체가 값어치다** — 어제 O 였던 칸이 오늘 X 가 되면
아무도 그 도구를 못 믿는다.

검수기준 61개 항목의 「판정 주체」 배분:

| 주체 | 항목 수 |
|---|---|
| 모형 | 44 |
| 계산 (코드) | 15 |
| 사람 | 2 |

그리고 모형이 뭐라 하든 **코드가 지키는 것**이 `core.ask` 에 있다.
시트를 통째로 맡기는 설계라 가끔 어긋나는데, 그대로 검사 칸에 옮기면
학교에 잘못 나간다.

## 산출물

```
서울대검증문서.xlsx                        학교 원본 — 건드리지 않는다
서울대검증문서_보조_검사결과_⑤인턴십.xlsx    ★ 최종.  O · X · 확인 불가
서울대검증문서_보조_추출내역_⑤인턴십.xlsx    왜 그렇게 됐나 — 되짚는 길
증빙/text_cache/                          증빙 원문.  다시 검사할 때 안 읽는다
증빙/_보조_판정보고.json                    칸마다의 판정과 근거
```

검사 칸에는 넉 자만 들어간다. **왜 그렇게 됐는지는 추출 내역에 있다.**
시트를 통째로 맡기는 설계에서 그 '왜' 를 잃으면 아무도 결과를 못 믿는다.

추출 내역의 장 구성:

- **개요** — 한눈에 · 봐야 할 것
- **&lt;시트&gt;** — 줄마다 두 줄. 위는 엑셀에 적힌 값, 아래는 증빙에서 뽑은 값
- **판정** — 줄 × 검증열 격자. 칸에 마우스를 올리면 근거가 나온다
- **남은 것** — 못 맺은 줄 · 어느 줄에도 안 쓰인 파일

⚠ 산출물에는 **학생 이름과 증빙 원문**이 들어 있다. 공유드라이브에 올리지 않는다.

## 폴더

```
grad-rescue/
├─ run.py                  실행
├─ preflight.py            시작 전 라이브러리 점검 (한국어 안내)
├─ paths.py                자기 파일을 어디서 찾나 — 묶었을 때 프로그램파일/
│
├─ docs/
│   └─ 보조도구 검수기준.xlsx   ★ 정본.  빌드 필수 입력물
│
├─ core/                   판정 층
│   ├─ spec.py               검수기준을 읽는다 — 유일한 문
│   ├─ book.py               학교 엑셀을 읽는다
│   ├─ prompt.py             글 한 장으로 편다 — 이 도구의 심장
│   ├─ ask.py                모형에게 묻고, 낸 답을 코드가 검사한다
│   ├─ calc.py               수와 날짜는 코드가 센다
│   ├─ report.py             추출 내역 엑셀
│   └─ flow.py               여섯을 잇는다.  화면은 이 파일만 만난다
│
├─ engines/                입출력 층 (검수도구 3단계에서 승계)
│   ├─ read.py               파일 → 텍스트 (hwp · hwpx · docx · pdf)
│   ├─ ocr.py                그림 PDF → 텍스트 (Document AI)
│   └─ write.py              판정 보고 → 검사 칸.  기입만 한다
│
├─ ui/                     화면.  판정 로직 없음
├─ tools/                  검수기준 엑셀 만들기 · 연기 시험
├─ secrets/                열쇠 (.gitignore 로 막힘)
├─ build.py  build.spec    배포본 만들기
└─ 배포_안내.md  배포본_점검표.txt
```

**경계를 지킨다.** `engines/` 는 판정하지 않고, `ui/` 는 판정 로직을 모른다.
`core.spec` 말고는 아무도 검수기준을 모른다.

## 돌려 보기

```bash
pip install -r requirements.txt
```

`secrets/.env` 를 만든다.

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5-mini
```

그림으로만 된 PDF 를 읽어야 하면 Google Document AI 서비스계정 JSON 도
같은 폴더에 넣는다. 이름은 무엇이든 된다.

```bash
python run.py
```

**열쇠가 없으면 아무것도 못 한다.** 이 도구는 시트 하나를 통째로 모형에게
맡기는 것이 전부다. (검수도구는 0·1단계가 모형 없이도 돌았다.)

### 넣을 것

- 검사 칸(주황 FCE4D6)이 든 성과관리현황 엑셀
  → 칸이 없으면 검수도구로 [준비하기] 를 먼저 한다
- 증빙 폴더 하나
- `docs/보조도구 검수기준.xlsx` (자리에 있어야 한다)

## 배포본 만들기

```bash
python build.py             열쇠를 함께 넣는다 (기본)
python build.py --no-keys   열쇠 없이 — .env 를 따로 전달할 때
```

여섯 단계를 밟는다. 빌드 전 점검 → 묶기 → 검수기준을 exe 옆에 →
`secrets/` → 열쇠가 샜는지 전수 검사 → zip.

**검수기준 엑셀은 `프로그램파일/` 안이 아니라 exe 바로 옆에 둔다.**
사람이 열어 고치는 물건이라 라이브러리 수백 개가 든 폴더에 숨기면
아무도 못 찾는다.

```
보조도구/
    보조도구.exe
    보조도구 검수기준.xlsx        ← 여기를 고치면 검사 규칙이 바뀐다
    엑셀_넣기_전에_읽어주세요.txt
    secrets/                    열쇠
    프로그램파일/                 읽을거리 · 라이브러리 (건드리지 않는다)
```

> 폴더 이름 `프로그램파일` 은 세 곳이 같아야 한다 —
> `paths.py` 의 `INNER` · `build.spec` 의 `contents_directory` · `build.py` 의 `INNER`.

나눠 주기 전에 `배포본_점검표.txt` 를 손으로 5분 짚는다.
빌드가 됐다고 도는 것은 아니다.

### ⚠ 기본이 「열쇠 함께」다

`python build.py` 는 `secrets/` 의 `.env` 와 모든 `*.json` 을 배포본에 넣는다.
받는 사람이 바로 실행할 수 있게 한 것인데, **그 zip 이 밖으로 나가면
열쇠도 함께 나간다.** 파일 이름에 `_열쇠포함` 이 박히니 그것으로 구분한다.

손으로 다시 압축하지 않는다 — 그 표식이 지워지고, 윈도우 기본 압축은
한글 이름을 깨뜨린다.

## 저장소에 올리면 안 되는 것

`.gitignore` 가 둘을 먼저 막는다.

1. **열쇠** — `.env` · Document AI 서비스계정 키 · 열쇠 든 배포 zip
2. **개인정보** — 학교 제출자료. 참여학생명 · 개인정보동의서가 들어 있다

반대로 **반드시 올려야 하는 것**이 하나 있다.
`docs/보조도구 검수기준.xlsx` 는 `*.xlsx` 전역 차단의 예외로 뚫어 두었다.
빌드 필수 입력물이라 이것이 없으면 클론한 사람은 빌드를 못 한다.

규칙을 고쳤으면 반드시 확인한다.

```powershell
git check-ignore -v -- "docs/보조도구 검수기준.xlsx"   # 아무것도 안 나와야 한다
git status --porcelain                                # 올라갈 것 전부
```

> `.gitignore` 는 **줄 끝 주석을 지원하지 않는다.**
> `*.zip  # 설명` 이라 쓰면 그 줄 전체가 패턴이 되어 아무것도 안 걸린다.

## 근거 문서

판정 기준의 최종 근거는 **「성과관리현황 검수과정정의서」** 다.
본 도구의 `보조도구 검수기준.xlsx` 는 그 판정에 이르는 추출·대조 절차를 정한 것으로,
양자가 상충하면 상위 문서를 따른다.

- 「성과관리현황 검수과정정의서」 (상위)
- 「[3단계] 파일 개봉 검수정의서 v1.1」
- 「특성화대학원 성과관리현황 제출 방법」 (4-2)
- 별지 제23호 서식 「인력양성 성과관리 현황」
